# ConvexAuth integration (Task 2.3) — recipe

Chosen: **ConvexAuth (`@convex-dev/auth` v0.0.95, self-contained Password provider)** against a
**local dev backend**. This is the auth unblocker that makes every `requireUser()` call succeed so
Phases 3-4 can render live Convex data.

Status: **not applied yet.** The backend ConvexAuth files are generated by an interactive setup CLI
that also writes env secrets to a running deployment, and it collides with our existing `users`
table (below). Applying it blind here would break the (currently green) web build, which type-checks
the backend through the `@convex/*` path alias. Run these at a terminal with the backend deployed,
then I can wire/verify the frontend.

---

## The one decision: who owns the `users` table

ConvexAuth expects a `users` table it manages (email/name/image + auth timestamps). Our backend
already has an app-scoped `users` table with `subject`, `role`, `institutionId`. They must be
reconciled. **Recommended:** let the ConvexAuth-managed `users` table also carry our fields, and key
off the ConvexAuth user id instead of `subject`.

Concretely (after setup):
- Add `role`, `institutionId`, `createdAt` to the `users` table (the app's `subject` becomes the
  ConvexAuth account linkage; drop the manual `by_subject` lookup).
- Rewrite `convex/auth.ts` helpers: `currentUser`/`requireUser` resolve the app `users` row by the
  signed-in ConvexAuth user id (from `ctx.auth` / `auth.getUserIdentity()` `subject`) rather than a
  raw OIDC `subject`.
- `users.ensureCurrent` becomes upsert-by-ConvexAuth-id.
- Update `seed.ts` demo user to a real email/password account (or a dev account) so the demo login
  works, keeping `role: "coordinator"`, `institutionId`.

Flag: this touches auth guards + seed; I'd do it as a focused edit and verify with `npx convex dev`
deploy + `npm run build` on the web.

## Backend (kaushalloop-convex)

1. `npm i @convex-dev/auth`  (already added in this copy)
2. Start a real dev deployment and let it register the auth component, then scaffold:
   ```
   npx convex dev                 # persistent; keeps a deployment + writes generated types
   npx @convex-dev/auth           # interactive setup: creates convex/auth.ts, convex/http.ts,
                                  # updates convex.json (auth component) + schema, and sets env secrets
   ```
   Providers to pick: **Password** (self-contained; no external SaaS). Add OAuth later if wanted.
3. Reconcile the `users` table per the decision above.
4. Env on the deployment (setup usually sets these; verify):
   ```
   npx convex env set CONVEX_AUTH_ACCESS_SECRET <random 44+ chars>
   npx convex env set CONVEX_AUTH_REFRESH_SECRET <random>
   npx convex env set SITE_URL http://localhost:3000
   ```
   Generate randoms: `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`
5. Gate a route handler so HTTP auth works: the setup writes `convex/http.ts` with
   `appRouter.add("/auth/*", auth.router)`.

## Frontend (kaushalloop-web) — the parts I can wire confidently

1. Replace the plain provider in `src/components/convex-provider.tsx`:
   ```tsx
   "use client";
   import { useConvexAuth, ConvexProviderWithConvexAuth } from "convex/react";
   import { convex } from "@/lib/convex";
   export function ConvexProvider({ children }: { children: React.ReactNode }) {
     return (
       <ConvexProviderWithConvexAuth client={convex} useConvexAuth={useConvexAuth}>
         {children}
       </ConvexProviderWithConvexAuth>
     );
   }
   ```
2. `src/lib/convex.ts` already reads `NEXT_PUBLIC_CONVEX_URL` — point it at the same dev URL the
   browser reaches (localhost is fine for local sign-in).
3. Sign-in page `src/app/sign-in/page.tsx` using the Password flow:
   ```tsx
   "use client";
   import { useAuthActions } from "@convex-dev/auth/react";
   // email + password form -> signIn({ flow: "password", email, password })
   // after success, users.ensureCurrent, then router.push("/").
   ```
   Use the Phase-1 `ReviewDecisionForm` pattern (react-hook-form + zod) for the fields.
4. Gate the `(app)` shell with `const { isLoading, isAuthenticated } = useConvexAuth()` — show a
   `SkeletonTable`/loading while authing, redirect to `/sign-in` when signed out.
5. Add a sign-out button in the header/sidebar footer (also `useAuthActions().signOut`).

dev code path that calls `requireUser`-equivalent with it. Not for prod; trivial to delete once
